# Руководство оператора

## Аннотация

Настоящий документ является программным документом "Руководство оператора" для клиентской части информационной системы T-Events Frontend. Документ составлен с учетом требований ГОСТ 19.505-79 и описывает назначение программы, условия ее выполнения, порядок работы оператора, основные пользовательские сценарии и сообщения, выдаваемые программой в процессе эксплуатации.

Программа T-Events Frontend представляет собой веб-приложение для проведения мероприятий с игровыми заданиями, начислением баллов, получением призов по QR-коду и административным управлением мероприятиями. В приложении предусмотрены роли участника, стендера и администратора.

Документ предназначен для операторов системы, администраторов мероприятий, стендеров, а также лиц, выполняющих приемочные, демонстрационные или учебные работы с программой.

## 1. Назначение программы

### 1.1. Общие сведения

T-Events Frontend предназначена для предоставления пользователям графического веб-интерфейса к системе мероприятий. Программа обеспечивает взаимодействие с backend API по HTTP и отображает данные о мероприятиях, направлениях, играх, игровом прогрессе, призах и выдачах.

Клиентская часть реализована как веб-приложение на базе Next.js, React и TypeScript. Программа выполняется в браузере пользователя и обращается к серверной части через маршруты с префиксом `/api/v1`.

### 1.2. Категории операторов

В программе используются следующие категории операторов:

| Категория оператора | Роль в системе | Назначение |
| --- | --- | --- |
| Участник | `participant` | Регистрация, вход, выбор мероприятия и направления, прохождение игр, просмотр прогресса, получение QR-кода на приз |
| Стендер | `stander` | Проверка QR-кода участника и подтверждение выдачи приза |
| Администратор | `admin` | Создание и настройка мероприятий, управление направлениями, игровыми шаблонами, расписанием, публикацией и архивированием |

Администратор также может выполнять функции стендера, если это разрешено серверной частью.

### 1.3. Основные функции программы

Программа обеспечивает выполнение следующих функций:

- просмотр списка активных мероприятий;
- регистрация нового пользователя по электронной почте, паролю, ФИО и телефону;
- вход пользователя по электронной почте и паролю;
- вход через VK OAuth при наличии настроенной серверной авторизации;
- автоматическое обновление access-токена с использованием refresh-cookie;
- выбор мероприятия и направления;
- просмотр списка игр в выбранном направлении;
- запуск или продолжение игровой сессии;
- прохождение игр типов `question_answer` и `quiz`;
- отображение текущего количества баллов, прогресса по вопросам и статуса игры;
- расчет и отображение прогресса до малого и большого приза;
- формирование QR-кода на приз при достижении порога;
- сканирование или ручной ввод QR-токена стендером;
- предварительная проверка права на выдачу приза;
- подтверждение выдачи приза;
- просмотр списка выданных призов стендером;
- создание черновиков мероприятий администратором;
- редактирование названия, описания, расписания, часового пояса и порогов призов;
- добавление и удаление направлений мероприятия;
- подключение игровых шаблонов к направлениям;
- настройка количества вопросов и баллов по уровням сложности;
- публикация и архивирование мероприятий.

### 1.4. Ограничения и особенности эксплуатации

Программа не хранит постоянные бизнес-данные самостоятельно. Данные мероприятий, пользователей, игровых сессий, QR-кодов и выдач хранятся на backend-сервере.

В браузере пользователя сохраняется access-токен авторизации. Refresh-токен хранится сервером в HttpOnly-cookie с путем `/api/v1/auth/refresh`.

Для работы сканера QR-кодов требуется браузер с поддержкой доступа к камере. При отсутствии доступа к камере стендер может ввести токен или ссылку из QR-кода вручную.

Пользователь с ролью участника не имеет доступа к административным разделам и стендерским операциям. При попытке открыть недоступный раздел программа перенаправляет пользователя на доступную страницу или отображает сообщение об отсутствии доступа.

## 2. Условия выполнения программы

### 2.1. Минимальный состав аппаратных средств

Для выполнения программы на стороне оператора требуется:

- персональный компьютер, ноутбук, планшет или смартфон;
- процессор с производительностью, достаточной для современного браузера;
- не менее 4 ГБ оперативной памяти для настольного устройства или эквивалентные ресурсы мобильного устройства;
- экран с разрешением не ниже 360 пикселей по ширине для мобильного интерфейса;
- устройство ввода: клавиатура, мышь, сенсорный экран или их аналоги;
- камера для стендерского сценария сканирования QR-кодов.

Для разработки и локального запуска требуется рабочая станция, способная выполнять Node.js-приложения.

### 2.2. Минимальный состав программных средств

Для эксплуатации программы в браузере требуется один из современных браузеров:

- Google Chrome;
- Microsoft Edge;
- Mozilla Firefox;
- Safari.

Для локального запуска и сопровождения фронтенд-приложения требуется:

- Node.js совместимой версии;
- npm;
- установленный пакет зависимостей проекта;
- backend-сервер T-Events, доступный по HTTP.

Используемые основные программные библиотеки:

| Средство | Назначение |
| --- | --- |
| Next.js | Фреймворк веб-приложения |
| React | Пользовательский интерфейс |
| TypeScript | Типизация исходного кода |
| TanStack React Query | Выполнение и кэширование запросов к API |
| react-hook-form и zod | Формы и проверка вводимых данных |
| qrcode.react | Отображение QR-кода |
| @zxing/browser | Сканирование QR-кода с камеры |
| Zustand | Локальное состояние выбранного участия |

### 2.3. Сетевые условия и серверная часть

Программа обращается к backend API по префиксу:

```text
/api/v1
```

При локальной разработке backend по умолчанию ожидается по адресу:

```text
http://localhost:8080
```

Проверка работоспособности backend-сервера выполняется запросом:

```http
GET /healthz
```

Ожидаемый успешный ответ:

```json
{
  "data": {
    "status": "ok"
  }
}
```

Все защищенные запросы выполняются с заголовком:

```http
Authorization: Bearer <access_token>
```

Для обновления сессии программа выполняет запрос:

```http
POST /api/v1/auth/refresh
```

Запросы, изменяющие данные, при наличии cookie `csrf_token` дополнительно отправляют заголовок `X-CSRF-Token`.

### 2.4. Учетные записи и права доступа

Для работы с программой требуются учетные записи с соответствующими ролями:

- участник может быть зарегистрирован через форму регистрации или внешний вход через VK;
- стендер должен иметь роль `stander` или `admin`;
- администратор должен иметь роль `admin`.

Операции, выполняемые без авторизации:

- просмотр главной страницы;
- просмотр списка активных мероприятий;
- регистрация;
- вход;
- начало VK OAuth;
- callback VK OAuth.

Операции, требующие авторизации:

- просмотр личного участия;
- прохождение игр;
- получение QR-кода на приз;
- выдача приза;
- административное управление мероприятиями.

### 2.5. Переменные окружения и запуск

Для локальной разработки используется переменная окружения:

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `BACKEND_API_ORIGIN` | `http://localhost:8080` | Адрес backend-сервера для Next.js rewrites |

Основные команды обслуживания:

| Команда | Назначение | Ответ программы |
| --- | --- | --- |

| `npm run dev` | Запуск в режиме разработки | Запуск локального dev-сервера Next.js |
| `npm run build` | Сборка production-версии | Создание оптимизированной сборки или вывод ошибки сборки |
| `npm run start` | Запуск production-сервера после сборки | Запуск собранного приложения |
| `npm run lint` | Статическая проверка кода | Список нарушений или успешное завершение |
| `npm run test` | Запуск тестов | Результаты выполнения тестов |

## 3. Выполнение программы

### 3.1. Подготовка к работе

Перед началом работы оператор должен:

1. Убедиться, что backend-сервер запущен и доступен.
2. Убедиться, что frontend-приложение запущено или опубликовано на сервере.
3. Открыть приложение в браузере.
4. Проверить доступность страницы мероприятий.
5. При необходимости выполнить вход в учетную запись.

Для стендера дополнительно требуется:

1. Убедиться, что учетная запись имеет роль `stander` или `admin`.
2. Разрешить браузеру доступ к камере при использовании сканера QR-кодов.

Для администратора дополнительно требуется:

1. Убедиться, что учетная запись имеет роль `admin`.
2. Проверить наличие доступных игровых шаблонов на backend-сервере.

### 3.2. Загрузка и запуск программы

Для локального запуска программы оператор выполняет:

```bash
cd t-events-frontend
npm ci
npm run dev
```

После запуска dev-сервера программа доступна в браузере по адресу, указанному Next.js в терминале. В типовом случае используется:

```text
http://localhost:3000
```

Если порт занят, Next.js может предложить другой порт. Оператор должен открыть фактически выведенный адрес.

Для production-запуска выполняется:

```bash
npm run build
npm run start
```

Ответ программы при успешном запуске: веб-сервер принимает HTTP-запросы, а браузер отображает главную страницу или страницу мероприятий.

### 3.3. Завершение работы программы

Для завершения локального dev-сервера оператор в терминале нажимает:

```text
Ctrl+C
```

После завершения frontend-сервер перестает обслуживать страницы приложения. Текущие данные пользователей не удаляются, так как хранятся на backend-сервере.

Для завершения пользовательской сессии в браузере оператор закрывает вкладку или выполняет выход, если соответствующая команда доступна в интерфейсе. При истечении access-токена программа пытается обновить его автоматически через refresh-cookie.

### 3.4. Вход и регистрация пользователя

#### 3.4.1. Регистрация

Оператор открывает страницу:

```text
/auth/register
```

Последовательность действий:

1. Ввести электронную почту.
2. Ввести пароль длиной не менее 6 символов.
3. Ввести ФИО в формате "Фамилия Имя Отчество". Если отчества нет, в третьей части указать дефис.
4. Ввести телефон.
5. Нажать кнопку регистрации.

При успешной регистрации программа сохраняет access-токен, получает данные пользователя и перенаправляет оператора на целевую страницу, обычно `/events`.

Альтернативный вариант: нажать вход через VK, после чего программа передает управление внешнему OAuth-сценарию.

#### 3.4.2. Вход

Оператор открывает страницу:

```text
/auth/login
```

Последовательность действий:

1. Ввести электронную почту.
2. Ввести пароль.
3. При необходимости нажать кнопку показа пароля.
4. Нажать кнопку входа.

При успешном входе программа сохраняет access-токен, получает данные пользователя и перенаправляет оператора на целевую страницу.

### 3.5. Работа участника мероприятия

#### 3.5.1. Просмотр мероприятий

Оператор открывает:

```text
/events
```

Программа отображает список активных мероприятий. Если мероприятий нет, отображается пустое состояние. Если ранее было выбрано мероприятие и направление, программа может показать блок продолжения участия.

#### 3.5.2. Выбор направления

Оператор выбирает мероприятие из списка. Программа открывает страницу направлений:

```text
/events/{event_id}/directions
```

Оператор выбирает направление. Выбранное мероприятие и направление сохраняются в локальном состоянии браузера для быстрого продолжения участия.

#### 3.5.3. Просмотр игр направления

После выбора направления оператор открывает:

```text
/events/{event_id}/directions/{direction_id}/games
```

Программа отображает:

- название направления;
- текущий прогресс по направлению;
- пороги малого и большого приза;
- список игр;
- статус каждой игры: не начата, в процессе, завершена;
- набранные и максимальные баллы;
- количество отвеченных вопросов.

Для игры в статусе "не начата" доступна команда "Начать". Для игры в статусе "в процессе" доступна команда "Продолжить". Завершенная игра повторно недоступна.

#### 3.5.4. Прохождение игры

При выборе игры программа открывает:

```text
/events/{event_id}/directions/{direction_id}/games/{event_game_id}
```

Программа автоматически создает новую игровую сессию или продолжает существующую. Во время игры отображаются:

- название игры;
- количество текущих и максимальных баллов;
- количество отвеченных и всего вопросов;
- статус сессии;
- текст текущего вопроса;
- сложность вопроса;
- количество баллов за вопрос.

Для игры типа `question_answer` оператор вводит текстовый ответ и нажимает кнопку отправки.

Для игры типа `quiz` оператор выбирает один из предложенных вариантов. Выбор может выполняться мышью, сенсорным экраном или клавиатурой. После выбора оператор отправляет ответ.

После отправки ответа программа отображает результат ответа, начисленные баллы и обновленный прогресс по направлению. Если вопросы закончились, игра получает статус завершенной.

#### 3.5.5. Просмотр прогресса

Оператор может открыть страницу прогресса направления:

```text
/events/{event_id}/directions/{direction_id}/progress
```

Программа отображает сведения о набранных баллах, максимальном количестве баллов, прогрессе по направлению и доступности призов.

### 3.6. Получение приза участником

Оператор открывает страницу приза:

```text
/events/{event_id}/directions/{direction_id}/reward
```

Программа запрашивает статус права на приз. Возможные состояния:

| Состояние | Значение |
| --- | --- |
| `locked` | Приз пока недоступен |
| `small_unlocked` | Доступен малый приз |
| `big_unlocked` | Доступен большой приз |
| `redeemed` | Приз уже получен |

Если приз доступен, оператор формирует QR-код. QR-код предъявляется стендеру для проверки и выдачи приза. Если приз уже был выдан, повторная выдача блокируется сервером.

### 3.7. Работа стендера при выдаче приза

Стендер открывает:

```text
/stander/scan
```

Последовательность действий при сканировании:

1. Нажать кнопку включения камеры.
2. Разрешить браузеру доступ к камере.
3. Навести камеру на QR-код участника.
4. Дождаться предварительной проверки QR-кода.
5. Проверить данные участника, мероприятия, направления и типа приза.
6. Если QR-код активен и приз не был выдан, подтвердить выдачу.

Последовательность действий при ручном вводе:

1. Вставить токен или ссылку из QR-кода в поле ввода.
2. Нажать кнопку проверки QR.
3. Проверить данные предварительного просмотра.
4. Подтвердить выдачу.

После подтверждения программа отображает состояние успешной выдачи. QR-код является одноразовым, повторное подтверждение того же QR-кода не допускается.

Дополнительно стендер может открыть страницу:

```text
/stander/inventory
```

На этой странице отображается список выдач по мероприятию с возможностью поиска и фильтрации, если соответствующие данные доступны на сервере.

### 3.8. Работа администратора мероприятий

#### 3.8.1. Просмотр и создание мероприятий

Администратор открывает:

```text
/admin/events
```

На странице отображается список мероприятий с их статусами, количеством направлений и игр. Для создания нового мероприятия администратор:

1. Вводит название нового черновика.
2. Нажимает кнопку создания.
3. После успешного создания программа открывает карточку мероприятия.

#### 3.8.2. Редактирование мероприятия

Администратор открывает:

```text
/admin/events/{event_id}
```

На странице можно изменить:

- название;
- описание;
- время начала;
- время окончания;
- часовой пояс;
- процент малого приза;
- процент большого приза.

Для расписания используется формат локального времени выбранного часового пояса. При отправке программа преобразует значения в RFC 3339, например:

```text
2026-05-10T12:00:00+03:00
```

Программа проверяет обязательность полей, корректность процентов и то, что время окончания позже времени начала.

#### 3.8.3. Управление направлениями

Администратор указывает идентификатор направления и добавляет его к мероприятию. Для удаления направления администратор указывает идентификатор направления и выполняет удаление.

Удаление направления может быть запрещено, если в направлении уже есть игры.

#### 3.8.4. Управление играми

Администратор выбирает игровой шаблон, направление и настраивает конфигурацию игры:

- количество вопросов уровня `easy`;
- количество вопросов уровня `medium`;
- количество вопросов уровня `hard`;
- баллы за вопросы каждого уровня сложности.

Значения количества вопросов не могут быть отрицательными. Если количество вопросов выбранного уровня больше нуля, баллы за этот уровень должны быть положительными.

После подключения игры программа отображает сведения о последней добавленной или измененной игре.

#### 3.8.5. Публикация и архивирование

После заполнения данных мероприятия, настройки направлений и игр администратор может выполнить публикацию. Если сервер обнаружит нарушения, программа отобразит список причин, по которым публикация невозможна.

Администратор может архивировать мероприятие. После архивирования дальнейшие действия с мероприятием ограничиваются правилами backend-сервера.

### 3.9. Форматы команд оператора и ответы программы

В графическом интерфейсе команды оператора представлены кнопками, ссылками, полями ввода и элементами выбора. Основные команды приведены в таблице.

| Команда оператора | Где выполняется | Действие программы | Возможный ответ программы |
| --- | --- | --- | --- |
| Зарегистрироваться | `/auth/register` | Отправляет данные регистрации | Переход к мероприятиям или сообщение об ошибке |
| Войти | `/auth/login` | Проверяет учетные данные | Переход к целевой странице или сообщение о неверных данных |
| Войти через VK | `/auth/login`, `/auth/register` | Открывает OAuth-сценарий | Возврат в приложение после авторизации |
| Открыть мероприятие | `/events` | Загружает направления мероприятия | Отображение направлений или ошибка загрузки |
| Начать | Список игр | Создает или возобновляет сессию | Открытие страницы игры |
| Продолжить | Список игр | Возобновляет активную сессию | Открытие страницы игры |
| Отправить ответ | Страница игры | Отправляет ответ на текущий вопрос | Результат ответа, новые баллы, следующий вопрос |
| Получить приз | Список игр или страница приза | Открывает статус приза и QR | QR-код или сообщение о недоступности |
| Включить камеру | `/stander/scan` | Запрашивает доступ к камере | Активный видеопоток или ошибка камеры |
| Проверить QR | `/stander/scan` | Проверяет QR-токен | Предварительный просмотр или ошибка |
| Подтвердить выдачу | `/stander/scan` | Фиксирует выдачу приза | Сообщение об успешной выдаче или отказ |
| Создать | `/admin/events` | Создает черновик мероприятия | Переход к карточке мероприятия |
| Сохранить изменения | `/admin/events/{id}` | Обновляет данные мероприятия | Обновленные данные или ошибки полей |
| Опубликовать | `/admin/events/{id}` | Публикует мероприятие | Новый статус или причины отказа |
| Архивировать | `/admin/events/{id}` | Переводит мероприятие в архив | Подтверждение архивирования или ошибка |

## 4. Сообщения оператору

### 4.1. Информационные сообщения

| Текст сообщения | Содержание | Действия оператора |
| --- | --- | --- |
| `Загрузка...` | Выполняется получение данных | Дождаться завершения |
| `Загрузка мероприятий...` | Получается список мероприятий | Дождаться загрузки или повторить при ошибке |
| `Загрузка списка игр...` | Получается список игр направления | Дождаться загрузки |
| `Загрузка сессии...` | Открывается игровая сессия | Дождаться отображения вопроса |
| `Открытие...` | Выполняется переход к игре | Дождаться перехода |
| `Проверка...` | Выполняется проверка QR-кода | Дождаться результата |
| `Обновление...` | Выполняется повторная загрузка данных | Дождаться завершения |

### 4.2. Сообщения проверки данных

| Текст сообщения | Содержание | Действия оператора |
| --- | --- | --- |
| `Некорректный адрес электронной почты` | Email введен в неверном формате | Исправить email |
| `Минимум 6 символов` | Пароль слишком короткий | Ввести пароль длиной не менее 6 символов |
| `Введите телефон` | Не заполнен телефон | Заполнить поле телефона |
| `Введите фамилию, имя и отчество...` | ФИО не соответствует ожидаемому формату | Ввести три части ФИО или дефис вместо отчества |
| `Название обязательно` | Не заполнено название мероприятия | Ввести название |
| `Описание обязательно` | Не заполнено описание мероприятия | Ввести описание |
| `Время начала обязательно` | Не заполнено начало мероприятия | Указать дату и время |
| `Время окончания обязательно` | Не заполнено окончание мероприятия | Указать дату и время |
| `Время окончания должно быть позже времени начала` | Расписание задано некорректно | Исправить время |
| `Процент малого приза должен быть от 1 до 100` | Некорректный порог малого приза | Ввести число от 1 до 100 |
| `Процент большого приза должен быть больше процента малого приза` | Нарушено соотношение порогов | Увеличить процент большого приза |

### 4.3. Сообщения авторизации и доступа

| Текст сообщения | Содержание | Действия оператора |
| --- | --- | --- |
| `Необходимо войти в аккаунт` | Открыта защищенная страница без авторизации | Перейти на страницу входа |

| `Аккаунт создан. Теперь войдите...` | Регистрация завершена, требуется вход | Выполнить вход |

### 4.4. Сообщения игровых сценариев

| Текст сообщения | Содержание | Действия оператора |

| `Мероприятие неактивно` | Игровой сценарий недоступен из-за статуса мероприятия | Выбрать другое мероприятие |
| `Игра не относится к выбранному направлению` | Адрес игры некорректен | Вернуться к списку игр направления |

| Текст сообщения | Содержание | Действия оператора |

| `Можно выдать` | QR активен, выдача доступна | Проверить данные и подтвердить выдачу |

| `Редактирование недоступно` | Мероприятие нельзя редактировать в текущем статусе | Проверить статус мероприятия |

| `Публикация недоступна` | Не выполнены условия публикации | Заполнить поля, направления и игры согласно списку ошибок |

### 4.7. Сообщения сетевых и серверных ошибок

| Текст сообщения | Содержание | Действия оператора |
| --- | --- | --- |
| `Не удалось подключиться к серверу. Проверьте соединение` | Браузер не получил ответ backend-сервера | Проверить сеть, адрес backend и состояние сервера |
| `Не удалось выполнить сетевой запрос` | Сетевой запрос завершился ошибкой | Повторить действие после проверки соединения |
| `Сервер вернул ошибку` | Получен HTTP-ответ с ошибкой | Повторить действие или обратиться к администратору |
| `Сервис временно недоступен` | Backend временно не обслуживает запрос | Повторить позже |
| `Внешний сервис недоступен` | Ошибка внешней интеграции, например OAuth | Повторить позже |
| `На сервере произошла ошибка` | Внутренняя ошибка backend-сервера | Повторить позже или передать сведения разработчику |
| `Запрошенный ресурс не найден` | Объект отсутствует или адрес некорректен | Проверить выбранное мероприятие, направление или игру |

При повторяющихся ошибках оператор должен зафиксировать:

1. Адрес страницы.
2. Выполняемую команду.
3. Текст сообщения.
4. Время возникновения ошибки.
5. Роль пользователя.

Эти сведения передаются администратору или разработчику для диагностики.
